# V2.8.8 技术要点总结笔记

## 一、编码与加密的区别及方法分类

### 1.1 编码（Encoding）vs 加密（Encryption）

| 特性 | 编码（Encoding） | 加密（Encryption） |
|------|----------------|-------------------|
| **目的** | 数据格式转换 | 数据安全保护 |
| **可逆性** | 必然可逆（有明确解码规则） | 理论上可逆（需密钥解密）或不可逆（哈希） |
| **是否保密** | 否，用于兼容传输 | 是，防止数据泄露 |
| **常见算法** | Base64、URL编码、UTF-8 | MD5、AES、RSA、SHA |

### 1.2 本项目中涉及的加密方法分类

#### 1.2.1 哈希加密（单向加密，不可逆）

**MD5+Salt** —— 密码安全存储

```java
// 注册时密码加密
String encodePassword = DigestUtil.md5Hex(password + salt);
User user = new User()
    .setPhone(phone)
    .setPassword(encodePassword)  // 存储加密后的密码
    .setSalt(salt);              // 存储盐值
```

**使用要点：**
- `DigestUtil.md5Hex()`：Hutool提供的MD5哈希工具，返回十六进制字符串
- **盐值（Salt）**：每个用户独立随机生成，防止彩虹表攻击
- 密码比对时：`encodePassword = md5Hex(用户输入的密码 + 用户存储的盐值)`

**注意：** MD5已不推荐用于密码存储，更安全的方案是bcrypt、PBKDF2或SCrypt。

#### 1.2.2 对称加密/非对称加密（双向）

本项目使用 **JWT（JSON Web Token）**，属于自包含令牌，内部使用 **HS256**（HMAC-SHA256）签名算法，本质是带签名的加密。

```java
// JWT签名算法
Jwts.builder()
    .setSubject(String.valueOf(userJson))  // 载荷内容
    .setIssuedAt(new Date())               // 签发时间
    .setExpiration(new Date(System.currentTimeMillis() + 1000 * 60 * 60 * 24)) // 24小时过期
    .signWith(Keys.hmacShaKeyFor(SECRET.getBytes()), SignatureAlgorithm.HS256) // HS256签名
    .compact();
```

#### 1.2.3 JSON序列化（不是加密，是数据格式化）

**关键要求：** cookie中的value和sign中的token都必须序列化！

```java
// ✗ 错误做法：直接传userId为字符串
String token = "12345"; 

// ✓ 正确做法：先序列化为JSON，再作为token主体
UserDTO userDTO = new UserDTO().setUserId(userId);
ObjectMapper objectMapper = new ObjectMapper();
String json = objectMapper.writeValueAsString(userDTO);  // 序列化为JSON字符串
String token = JwtUtil.createToken(json);               // JSON作为payload
```

**序列化原因：**
- 可携带更多字段（userType、createTime等），便于扩展
- 保证数据结构一致性
- 反序列化后可还原对象

### 1.3 方法分类总结

| 类别 | 方法/工具 | 使用位置 | 说明 |
|------|----------|----------|------|
| 哈希加密 | `DigestUtil.md5Hex()` | UserService | 密码MD5+salt加密 |
| JSON序列化 | `ObjectMapper.writeValueAsString()` | UserService | 对象转JSON |
| JSON反序列化 | `objectMapper.readValue()` | JwtUtil | JSON转对象 |
| JWT生成 | `JwtUtil.createToken()` | UserService | 生成签名token |
| JWT解析 | `JwtUtil.getUserId()` | 校验处 | 从token获取userId |
| Base64编码 | （未使用） | - | 用于图片base64传输 |
| URL编码 | `URLEncoder.encode()` | MusicController | 文件名编码 |

## 二、Cookie和Session机制总结

### 2.1 基本概念对比

| 特性 | Cookie | Session |
|------|--------|---------|
| **存储位置** | 客户端浏览器 | 服务器端（内存/Redis等） |
| **存储容量** | 较小（通常4KB） | 较大，受限于服务器内存 |
| **安全性** | 较低（客户端可篡改） | 较高（服务器端存储） |
| **性能** | 每次请求都携带 | 需查服务器存储 |
| **失效方式** | 过期时间/关闭浏览器 | 服务器端超时/销毁 |
| **跨域支持** | 需特殊配置 | 天然不跨域 |

### 2.2 Cookie的使用细节

```java
// 设置Cookie
Cookie cookie = new Cookie("sign", token);
cookie.setHttpOnly(true);    // 禁止JavaScript访问，防止XSS
cookie.setMaxAge(3600);      // 设置过期时间（秒），浏览器关闭失效
cookie.setPath("/");         // 生效路径，/表示全站有效
response.addCookie(cookie);  // 添加到响应头
```

**注意事项：**
- `setHttpOnly(true)`：防止XSS攻击窃取cookie
- `setSecure(true)`：仅HTTPS传输（生产环境建议）
- 需要配合Session一起使用，cookie中只存session ID或token

### 2.3 Session的使用细节

```java
// 获取或创建session
HttpSession session = request.getSession();  // 创建新session
HttpSession session = request.getSession(false); // 不创建，返回已存在的

// 存取数据
session.setAttribute("user", userId);        // 存储
Long userId = (Long) session.getAttribute("user"); // 读取
session.invalidate();                      // 销毁session
```

**Session生命周期：**
1. 用户首次访问时创建（默认30分钟）
2. 若用户在30分钟内无操作，session超时失效
3. 服务器重启可能导致session丢失（需Redis持久化）

## 三、JWT和Token/Sign机制总结

### 3.1 JWT（JSON Web Token）结构

JWT由三部分组成，用`.`连接：

```
Header.Payload.Signature
```

- **Header**：算法（HS256）和类型（JWT）
- **Payload**：用户信息（本例中为`{"userId":123}`）
- **Signature**：用密钥对Header+Payload的哈希签名，防止篡改

### 3.2 Token生成流程

```java
// UserService.adminLogin() - console端
String json = objectMapper.writeValueAsString(userDTO); // 1. 对象转JSON
String token = JwtUtil.createToken(json);             // 2. JWT生成

// JwtUtil.createToken()
Jwts.builder()
    .setSubject(json)           // 将JSON作为payload
    .setIssuedAt(new Date())
    .setExpiration(new Date(System.currentTimeMillis() + 24*60*60*1000))
    .signWith(Keys.hmacShaKeyFor(SECRET.getBytes()), SignatureAlgorithm.HS256)
    .compact();                // 生成签名token
```

### 3.3 Token校验流程

**App端（Header签名校验）：**

```java
// MusicController.java - 每个需要登录的方法
String token = request.getHeader("sign");    // 1. 从请求头获取
if (token == null) return null;              // 2. 判空

try {
    Long userId = JwtUtil.getUserId(token);  // 3. 解析token
} catch (JsonProcessingException e) {
    log.error("token解析失败");
    return null;
}
```

**注意：** App端是直接在每个Controller方法中手动校验，而非使用拦截器！

### 3.4 Token与Session的关系对比

| 对比项 | Cookie+Session（Console） | Token（App） |
|--------|--------------------------|--------------|
| **状态** | 有状态（服务端保存session） | 无状态（token自包含） |
| **验证方式** | 查session | 解析token签名 |
| **跨域支持** | 差（需配置cors） | 好（header携带） |
| **移动端友好** | 差（cookie需浏览器支持） | 好（header任意） |
| **扩展性** | session存服务器，扩展难 | token无状态，易扩展 |

## 四、App端登录注册与Console端登录差异

### 4.1 App端（移动端/API端）

**特点：** 不使用Cookie，使用Token（sign），无状态校验

#### 4.1.1 注册接口

```java
// UserController.java - App注册
@RequestMapping("/user/register")
public String register(@RequestParam(value = "phone") String phone,
                       @RequestParam(value = "password") String password,
                       @RequestParam(value = "name", required = false) String name,
                       @RequestParam(value = "avatar", required = false) String avatar) {
    phone = phone.trim();        // 前端trim + 后端trim双重校验
    password = password.trim();
    name = name.trim();
    String res = userService.register(phone, password, name, avatar);
    return new LoginVO().setSign(res);  // 返回token作为sign
}
```

**注册后自动登录：** 注册成功后，`userService.register()` 返回生成的token，直接作为sign返回给客户端，客户端无需再登录即可使用。

#### 4.1.2 登录接口

```java
// UserController.java - App登录
@RequestMapping("/user/login")
public String login(@RequestParam(value = "phone") String phone,
                    @RequestParam(value = "password") String password) {
    phone = phone.trim();
    password = password.trim();
    String res = userService.login(phone, password);
    return new LoginVO().setSign(res);
}
```

**token返回格式：** 返回纯token字符串（如`eyJhbGciOiJIUzI1NiJ9...`），客户端放入`sign` header。

#### 4.1.3 其他接口校验

```java
// MusicController.java - 每个方法单独校验
@RequestMapping("/music/info")
public MusicInfoVO getMusicInfoById(@RequestParam(value = "id") Long id, 
                                    HttpServletRequest request) {
    String token = request.getHeader("sign");    // 从header获取sign
    if (token == null) return null;              // 判空检查
    
    try {
        Long userId = JwtUtil.getUserId(token);  // 解析token
    } catch (JsonProcessingException e) {
        return null;
    }
    // 继续业务逻辑...
}
```

**特点：** 每个需要权限的方法都手动从`request.getHeader("sign")`获取token并校验，不依赖拦截器。

### 4.2 Console端（管理后台）

**特点：** 使用Cookie+Session，有状态校验

#### 4.2.1 登录接口

```java
// UserController.java - Console登录
@RequestMapping("/user/login")
public String login(@RequestParam(value = "phone") String phone,
                    @RequestParam(value = "password") String password,
                    HttpSession session,
                    HttpServletResponse response) {
    phone = phone.trim();
    password = password.trim();
    String res = userService.adminLogin(phone, password, session, response);
    return new LoginVO().setSign(res);
}
```

#### 4.2.2 登录处理（设置session和cookie）

```java
// UserService.java - adminLogin方法
public String adminLogin(String phone, String password, HttpSession session, HttpServletResponse response) 
        throws Exception {
    // 1. 验证密码
    User user = userMapper.extractByPhone(phone);
    String encodePassword = DigestUtil.md5Hex(password + user.getSalt());
    if (!encodePassword.equals(user.getPassword())) {
        throw new RuntimeException("密码错误");
    }
    
    // 2. 创建session并存储用户
    session.setAttribute("user", user.getId());   // 存userId到session
    
    // 3. 生成token
    UserDTO userDTO = new UserDTO().setUserId(user.getId());
    ObjectMapper objectMapper = new ObjectMapper();
    String json = objectMapper.writeValueAsString(userDTO);
    String token = JwtUtil.createToken(json);
    
    // 4. 设置cookie
    Cookie cookie = new Cookie("sign", token);
    cookie.setHttpOnly(true);
    cookie.setMaxAge(3600);
    cookie.setPath("/");
    response.addCookie(cookie);
    
    return token;  // 返回token作为sign
}
```

**Cookie设置说明：**
- `setHttpOnly(true)`：防止XSS
- `setPath("/")`：全站可用
- `setMaxAge(3600)`：1小时过期（可与session超时时间配合）

#### 4.2.3 拦截器校验

```java
// console/interceptor/LoginInterceptor.java
@Component
public class LoginInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        HttpSession session = request.getSession(false);  // 获取session（不创建）
        if (session == null) {
            throw new RuntimeException("未登录或登录已过期");
        }
        Object user = session.getAttribute("user");       // 从session取用户
        if (user == null) {
            throw new RuntimeException("请重新登录");
        }
        return true;  // 通过拦截，继续执行controller
    }
}
```

**WebConfig配置：**

```java
// console/config/WebConfig.java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Resource
    private LoginInterceptor loginInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/**")
                .excludePathPatterns("/user/login");  // 登录接口排除
    }
}
```

**特点：**
- 使用Spring MVC拦截器统一拦截所有请求（除登录接口）
- 通过Session判断是否登录，无状态校验
- 前端无需手动携带token，Cookie自动发送

### 4.3 差异对比表

| 特性 | App端 | Console端 |
|------|-------|-----------|
| **认证方式** | Token（sign header） | Cookie+Session |
| **校验方式** | 每个方法手动校验 | 拦截器统一校验 |
| **状态类型** | 无状态 | 有状态 |
| **客户端存储** | 客户端自行存token（localStorage/SharedPreferences） | 浏览器自动存cookie |
| **注册后登录** | 直接返回token，自动登录 | 登录成功后设置session和cookie |
| **跨域支持** | 好（header） | 需配置Cors |
| **安全性** | Token需自行防XSS | HttpOnly+Secure更安全 |
| **Session** | 无 | 有 |
| **URL示例** | `/music/info?sign=xxx`（header） | 浏览器自动携带cookie |

## 五、其他要点

### 5.1 md5+salt详细实现

#### 5.1.1 密码加密（注册时）

```java
// UserService.java - register方法
String salt = DigestUtil.randomHex(16);  // 生成16位随机盐
String encodePassword = DigestUtil.md5Hex(password + salt);

User user = new User()
    .setPhone(phone)
    .setPassword(encodePassword)
    .setSalt(salt)
    .setCreateTime(timeStamp)
    .setUpdateTime(timeStamp)
    .setIsDeleted((byte) 0);
userMapper.insert(user);
```

#### 5.1.2 密码校验（登录时）

```java
// UserService.java - login/adminLogin方法
User user = userMapper.extractByPhone(phone);
String encodePassword = DigestUtil.md5Hex(password + user.getSalt());  // 用存储的盐拼接

if (!encodePassword.equals(user.getPassword())) {
    throw new RuntimeException("密码错误");
}
```

**安全要点：**
- Salt必须随机生成且独立存储（不是固定值）
- 禁止使用裸密码存储
- 建议升级至BCrypt或PBKDF2（本版本为MD5+salt）

### 5.2 有状态 vs 无状态认证

| 维度 | 有状态（Session） | 无状态（Token/JWT） |
|------|-------------------|---------------------|
| **用户信息存储** | 服务器 | 客户端（token中） |
| **服务器压力** | 高（需存储所有session） | 低（无存储） |
| **注销方式** | 删除session即可 | 需黑名单或缩短过期时间 |
| **扩展性** | 差（session粘滞） | 好（任何实例可验证） |
| **本应用使用** | Console端 | App端 |

**本应用设计优势：** 双端分离，App用无状态适合移动端/跨平台，Console有状态适合后台管理系统（浏览器自动管理cookie）。

### 5.3 Cookie Value与Token序列化要求

**明确要求：** cookie中的value和sign中的token都要使用类序列化转为JSON，不直接使用String！

```java
// ✗ 错误做法：直接把userId放入token
String token = String.valueOf(userId);  // 12345，无法扩展

// ✓ 正确做法：先序列化再放入token
UserDTO userDTO = new UserDTO().setUserId(userId);
String json = objectMapper.writeValueAsString(userDTO);  // {"userId":12345}
String token = JwtUtil.createToken(json);
```

**反序列化：**

```java
// JwtUtil.getUserId()
String json = claims.getSubject();
UserDTO userDTO = objectMapper.readValue(json, UserDTO.class);  // 反序列化
return userDTO.getUserId();
```

**原因：** 若未来需要扩展（如增加userType、roleId等），只需扩展DTO，无需变更token格式。

### 5.4 request、response、session的区别与使用

| 对象 | 作用域 | 典型用法 | 本应用示例 |
|------|--------|----------|------------|
| **HttpServletRequest** | 单次请求 | 获取参数、header、属性 | `request.getHeader("sign")`、`request.getParameter()` |
| **HttpServletResponse** | 单次请求 | 设置响应头、写入响应 | `response.addCookie(cookie)`、`response.setContentType()` |
| **HttpSession** | 用户会话 | 跨请求存储用户状态 | `session.setAttribute("user", userId)` |

**注意：** session在Servlet生命周期中与request是独立的，但通过sessionId关联。

### 5.5 业务逻辑注意事项

#### 5.5.1 字符串trim处理

```java
// 所有用户输入均做trim，防止空格导致注册/登录失败
phone = phone == null ? phone : phone.trim();
password = password == null ? password : password.trim();
name = name == null ? name : trim();  // 注册时新增
```

**原因：** 用户输入可能包含前后空格，必须统一去除。

#### 5.5.2 空值处理与异常捕获

```java
// App端login/register
if (phone == null) phone = phone.trim();  // 空指针保护
// try-catch捕获异常，返回友好错误
try {
    res = userService.login(...);
} catch (Exception e) {
    log.error("登录失败", e);
    res = "登录失败";
}
```

**注意：** 生产环境不应直接将异常信息返回给客户端，应记录日志并返回通用错误信息。

#### 5.5.3 命名规范变更

```java
// UserVO → UserDTO
// VO（View Object）→ DTO（Data Transfer Object）
// 表意更准确：数据传输对象而非视图对象
// 文件路径重命名：UserVO.java → UserDTO.java
```

#### 5.5.4 环境变量敏感信息

```java
// JwtUtil.java
private final static String SECRET = System.getenv("JWT_SECRET");  // 从环境变量读取
```

**安全要点：** 密钥不应硬编码在代码中，应通过环境变量或密钥管理服务注入。

#### 5.5.5 方法异常声明变更

```java
// UserService中多个方法添加throws Exception
public User getById(Long id) throws Exception
public String login(String phone, String password) throws Exception
```

**原因：** 统一异常处理，便于上层调用捕获。

#### 5.5.6 删除App端拦截器和WebConfig

```diff
- app/config/WebConfig.java （已删除）
- app/interceptor/LoginInterceptor.java （已删除）
```

**原因：** App端改为每个方法单独校验，更灵活，适合API端风格。

## 六、完整调用流程示例

### 6.1 App端注册 → 自动登录 → 使用流程

```
1. 客户端发送POST /user/register (phone, password, name, avatar)
2. UserController.register() → userService.register()
3. UserService.register():
   - 生成随机salt
   - MD5(password+salt)加密密码
   - 插入数据库
   - 生成UserDTO → JSON → JWT token
   - 返回token（作为sign）
4. 客户端收到token，存入本地存储（localStorage/SharedPreferences）
5. 客户端调用其他接口时，在请求头添加：sign: <token>
6. MusicController.getMusicInfoById():
   - 从request.getHeader("sign")获取token
   - JwtUtil.getUserId(token)解析userId
   - 继续执行业务
```

### 6.2 Console端登录 → Session保存 → 拦截器校验流程

```
1. 客户端发送POST /user/login (phone, password)
2. UserController.login() → userService.adminLogin()
3. UserService.adminLogin():
   - MD5(password+盐)验证密码
   - session.setAttribute("user", userId)
   - 生成UserDTO → JSON → JWT token
   - 创建Cookie(sign=token)，添加到response
   - 返回token
4. 浏览器自动保存cookie
5. 客户端后续请求自动携带cookie
6. LoginInterceptor.preHandle():
   - request.getSession(false)获取session
   - session.getAttribute("user")校验用户
   - 通过则放行，否则抛异常
```

|--------|------|------|
| `DigestUtil` | `md5Hex(String)` | MD5加密 |
| `DigestUtil` | `randomHex(int)` | 生成随机盐 |
| `ObjectMapper` | `writeValueAsString(T)` | 对象转JSON |
| `ObjectMapper` | `readValue(String, Class)` | JSON转对象 |
| `JwtUtil` | `createToken(String)` | 生成JWT token |
| `JwtUtil` | `getUserId(String)` | 从token解析userId |
