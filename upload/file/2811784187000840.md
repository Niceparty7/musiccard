MyBatis-Plus（简称 **MP**）是基于 MyBatis 的增强框架，它**只增强，不改变**MyBatis，本质上还是MyBatis，只不过帮我们封装了大量重复的CRUD代码，提高开发效率。

如果把 MyBatis 比作手写 SQL，那么 MyBatis-Plus 就相当于在 MyBatis 上增加了一套"自动驾驶系统"。

------

# 一、MyBatis-Plus整体架构

```
Controller
      │
Service
      │
ServiceImpl（MP提供）
      │
Mapper（继承BaseMapper）
      │
MyBatis
      │
数据库
```

开发时通常只需要：

```
Entity
Mapper
Service
Controller
```

很多SQL甚至不用写。

例如：

以前MyBatis：

```java
@Mapper
public interface UserMapper {

    User selectById(Long id);

    int insert(User user);

    int delete(Long id);

    int update(User user);
}
```

XML：

```xml
<select id="selectById">
......
</select>

<insert>
......
</insert>
```

MyBatis-Plus：

```java
@Mapper
public interface UserMapper extends BaseMapper<User> {

}
```

结束。

所有CRUD已经有了。

# 四、条件构造器（Wrapper）

这是MP第二大功能。

不用自己拼SQL。

例如：

SQL：

```sql
select *
from user
where age>18
and gender=1
order by id desc
```

MP：

```java
QueryWrapper<User> wrapper = new QueryWrapper<>();

wrapper.gt("age",18)
       .eq("gender",1)
       .orderByDesc("id");

List<User> list =
userMapper.selectList(wrapper);
```

自动生成SQL。

# 五、LambdaQueryWrapper（推荐）

不用写字符串。

例如：

普通：

```java
wrapper.eq("user_name","Tom");
```

如果字段改名字：

```
user_name

↓

username
```

全部报错？

不会。

因为：

字符串不会报错。

直到运行才发现。

所以推荐：

```java
LambdaQueryWrapper<User> wrapper =
new LambdaQueryWrapper<>();

wrapper.eq(User::getUserName,"Tom");
```

IDE可以自动重构。

以后改字段：

```
getUserName()

↓

getName()
```

IDE全部修改。

不会出现字符串遗漏。

# 七、分页插件

MP提供分页。

配置：

```java
@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor interceptor(){

        MybatisPlusInterceptor interceptor =
                new MybatisPlusInterceptor();

        interceptor.addInnerInterceptor(
                new PaginationInnerInterceptor(DbType.MYSQL));

        return interceptor;
    }

}
```

查询：

```java
Page<User> page =
new Page<>(1,10);

Page<User> result =
userMapper.selectPage(page,null);
```

SQL：

第一页：

```
limit 0,10
```

第二页：

```
limit 10,10
```

返回：

```java
result.getRecords();

result.getTotal();

result.getPages();
```

# 九、自动填充

例如：

```
create_time

update_time
```

不用自己赋值。

实体：

```java
@TableField(fill = FieldFill.INSERT)
private LocalDateTime createTime;
```

配置：

```java
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }
}
```

以后：

```java
insert()
```

自动填充。

# 十七、自定义 SQL

MyBatis-Plus 并不限制你编写 SQL，当自动生成的方法无法满足复杂业务时，可以继续使用原生 MyBatis。

例如：

```java
@Mapper
public interface UserMapper extends BaseMapper<User> {

    List<User> selectActiveUsers();
}
```

对应 XML：

```xml
<select id="selectActiveUsers" resultType="User">
    select *
    from user
    where status = 1
</select>
```

因此，MyBatis-Plus 与 MyBatis 可以无缝结合：**简单 CRUD 用 MP，复杂查询写 XML 或注解 SQL**。

## MyBatis-Plus 功能总结

| 功能                   | 作用                        | 是否常用      |
| ---------------------- | --------------------------- | ------------- |
| BaseMapper             | 提供通用 CRUD               | ⭐⭐⭐⭐⭐         |
| IService / ServiceImpl | 通用 Service 层             | ⭐⭐⭐⭐⭐         |
| QueryWrapper           | 条件查询                    | ⭐⭐⭐⭐⭐         |
| LambdaQueryWrapper     | 类型安全条件查询            | ⭐⭐⭐⭐⭐（推荐） |
| LambdaUpdateWrapper    | 条件更新                    | ⭐⭐⭐⭐⭐         |
| 分页插件               | 自动分页查询                | ⭐⭐⭐⭐⭐         |
| 逻辑删除               | 软删除数据                  | ⭐⭐⭐⭐          |
| 自动填充               | 自动维护创建/更新时间等字段 | ⭐⭐⭐⭐          |
| 乐观锁                 | 并发更新控制                | ⭐⭐⭐⭐          |
| 主键策略               | 自增、雪花算法、自定义主键  | ⭐⭐⭐⭐          |
| 表/字段映射            | 实体与数据库映射            | ⭐⭐⭐⭐⭐         |
| 枚举映射               | 枚举与数据库值自动转换      | ⭐⭐⭐           |
| 代码生成器             | 自动生成基础代码            | ⭐⭐⭐⭐          |
| 自定义 SQL             | 保留 MyBatis 全部能力       | ⭐⭐⭐⭐⭐         |

对于实际开发（包括 Spring Boot 项目），最常用的组合通常是：**BaseMapper + IService/ServiceImpl + LambdaQueryWrapper/LambdaUpdateWrapper + 分页插件 + 逻辑删除 + 自动填充**。这几项已经能够覆盖绝大多数企业项目的日常数据库操作，而遇到复杂统计、联表查询、动态 SQL 等场景时，再结合 MyBatis 原生 XML 编写 SQL，既保持开发效率，又兼顾灵活性。



你的第二个观点我先回答：

> **我觉得应该放在 app 和 console 下，不应该放在 module 下。**

**我赞同。\**如果按照你的项目结构来看，`module` 更像是\**公共业务模块（Entity、Mapper、Service）**，而 `console` 和 `app` 才是真正的 Spring Boot 启动模块。

一般来说：

```text
musiccard
│
├── app                ← SpringBoot启动模块
│    ├── AppApplication.java
│    └── config
│         └── MybatisPlusConfig.java
│
├── console            ← SpringBoot启动模块
│    ├── ConsoleApplication.java
│    └── config
│         └── MybatisPlusConfig.java
│
└── module             ← 公共业务模块
     ├── entity
     ├── mapper
     ├── service
     └── ...
```

为什么？

因为：

- `MybatisPlusConfig` 是 **Spring 配置类**，不是业务代码。
- 它依赖 Spring IoC 容器。
- 只有启动模块才真正创建 Spring 容器。
- `module` 更适合作为一个可以复用的业务 Jar，不应该放运行环境相关的配置。

当然，如果整个项目只有一个启动类，放在 `module/config` 也能正常工作，只要包扫描能够扫描到即可。但从**模块职责划分**来说，放在启动模块的 `config` 包会更清晰。

## 接下来解释：为什么要注册 `MybatisPlusInterceptor Bean`

很多人第一次看到这段代码：

```java
@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {

        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        interceptor.addInnerInterceptor(
                new PaginationInnerInterceptor(DbType.MYSQL));

        return interceptor;
    }
}
```

都会疑惑：

> **为什么要注册一个 Bean？**

其实这和 Spring MVC 注册拦截器的思想非常类似。

------

# 一、什么是拦截器（Interceptor）？

可以理解为：

> **SQL 在真正发送给数据库之前，先经过一个"处理站"。**

流程如下：

```text
Controller
      │
Service
      │
Mapper
      │
生成SQL
      │
      ▼
MybatisPlusInterceptor   ⭐⭐⭐
      │
修改SQL
      │
      ▼
MySQL
```

没有拦截器：

```sql
select * from music
```

经过分页插件：

```sql
select *
from music
limit 0,10
```

SQL 被自动改写了。

------

# 二、为什么 Spring 要注册成 Bean？

Spring Boot 启动时会扫描：

```java
@Configuration
```

然后执行：

```java
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor()
```

得到：

```java
MybatisPlusInterceptor
```

放进 IOC 容器。

之后 MyBatis 初始化时：

```text
SqlSessionFactory
      │
      ▼
发现IOC里面有

MybatisPlusInterceptor
```

于是：

自动把它加入 MyBatis。

所以：

```java
@Bean
```

本质就是：

> **告诉 Spring："这里有一个 MP 拦截器，以后执行 SQL 时请使用它。"**

## 总结

- **`MybatisPlusInterceptor`**：MP 的统一拦截器管理器，本身不直接实现分页等功能，而是负责管理和调用各种内部插件（`InnerInterceptor`）。
- **`PaginationInnerInterceptor`**：分页插件，负责改写 SQL、执行总数统计、封装分页结果。
- **注册为 Spring Bean**：让 Spring 在启动时把它交给 MyBatis 使用，使所有 Mapper 的 SQL 都能自动经过这些插件处理。

因此，你可以把它理解成 **MyBatis-Plus 的总调度器**，以后无论是分页、乐观锁、多租户还是数据权限，都会通过它统一接入，而不是直接修改你的 Mapper 或 SQL。
